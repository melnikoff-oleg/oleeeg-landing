# Baseline audit, 2026-08-24

The state of oleg.ae's SEO at the moment this folder was created, read directly out of the codebase. Every later audit measures against this.

## Scale

- **35 page routes** under `src/app/` (excluding `api/`).
- Plus **~245 dynamic creator pages** at `/viral-reels-creators/[account]`, added to the sitemap at runtime from the database.
- Domain: `oleg.ae`. Traffic profile is YouTube-fed (about 84%), desktop-heavy, 1.48 pages per visit. Search is currently the missing channel, which is the whole reason this folder exists.

## Gaps found

Ordered roughly by what they cost. These are carried into `BACKLOG.md` with IDs.

### 1. No Open Graph images anywhere

Zero `opengraph-image` files, and no `images:` key in any metadata object site-wide. Every share to LinkedIn, X, Telegram or Slack renders as a bare text link. The root layout even declares `twitter.card = "summary_large_image"` while providing no image, so it asks for a large image card and supplies nothing.

This is the largest single miss. The site's traffic is social and YouTube-fed, which is precisely where OG images decide whether a link gets clicked.

### 2. Sitemap `lastModified` is `new Date()` on every entry

Every one of the 35 entries stamps the current time, re-evaluated hourly by `revalidate`. The sitemap therefore tells Google that all 35 pages changed within the last hour, every time it is fetched. Google discounts `lastModified` it cannot trust, so this actively devalues the one honest signal the sitemap could send about the pages that genuinely did change.

### 3. `/sam-altman-ai` is missing from the sitemap

Confirmed by diffing route folders against the sitemap URL list. It is the only route with a `page.tsx` and no sitemap entry. Its four filmed siblings (elon, boris, karpathy, riemann) are all listed.

### 4. No Person or WebSite schema on the homepage

`src/app/page.tsx` renders no JSON-LD at all. Person schema is a named to-do in CLAUDE.md and is the schema most likely to earn a knowledge-panel style treatment for "Oleg Melnikov" queries. `WebSite` schema with `sameAs` links would consolidate the entity across YouTube, LinkedIn and Instagram.

### 5. The troubleshooting blocks are FAQ content with no FAQPage schema

`src/components/troubleshooting.tsx` holds 10 real question-and-answer entries, built from clustering 593 YouTube comments, and they are rendered on 16 pages inside `<details>` elements. That is textbook FAQ markup that is currently invisible to search. These are also genuine long-tail queries ("claude not found", "credit balance", "gemini quota") that people type into Google verbatim.

### 6. No Google Search Console verification

No `google-site-verification` meta tag and no verification file. CLAUDE.md marks this as blocked and to revisit. It is worth unblocking: with the Plausible Stats API off the plan, Search Console is the only source of query-level data, and Ubersuggest's estimates are a proxy for it rather than a replacement.

### 7. Five pages have a private source video

`/claude-website`, `/claude-outreach`, `/claude-seo`, `/claude-interviewer`, `/claude-trend-scanner` all point at videos that now return `LOGIN_REQUIRED`. The pages were deliberately kept as standalone guides and they carry inbound `NextUp` links, which is a defensible call. But they are the weakest pages in the index and worth a content decision rather than being left in limbo. `/claude-website` in particular is fully superseded by `/high-converting-website`.

### 8. No Lighthouse or Core Web Vitals baseline

Real optimization work has shipped (see the table above) but has never been measured. There is no before number, so there is no way to know whether Core Web Vitals are passing or which page is the worst.

## Not a gap, do not "fix"

- **Missing canonicals.** There are none missing. If an audit tool reports otherwise it is reading a client-rendered snapshot.
- **The `/viral-reels*` pages having no content.** They are deliberately bare with an `sr-only` h1. A tool will flag them as thin content. That is the intended design.
- **The homepage not linking to resource pages.** Deliberate, see the README.
- **The filmed pages missing shared chrome.** `/elon-musk-ai`, `/boris-cherny-ai` and their siblings ship no header, no `ResourceFooter` and no client JavaScript on purpose, because a fast programmatic scroll during filming outruns the intersection observer. They carry a `FilmedPageOutro` for internal links instead.
